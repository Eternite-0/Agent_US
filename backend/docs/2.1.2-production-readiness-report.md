## 2. CI 失败根因

初始失败 Run：`44863457519`（SHA `fa8c01302adccd0a31ebec2d5f0829cc82058f60`）。公开 Actions/API 只能确认 Ubuntu Job `136721791379` 与 Windows Job `136721791631` 在 backend regression step 失败；原始日志端点受 GitHub 鉴权限制，未伪造不可见的远端日志行。

本地使用 `core.filemode=true` 复现并定位 Ubuntu 确定性根因：artifact 测试中的 `run.sh` executable mode 在父工作区 apply 时被内容 hash 相同的 `already_applied` 分支跳过，导致 `100755` 未恢复。另有 Windows 风险由未 await `direct.close()`、裸 `rmSync`、timer 泄漏、WAL/busy-timeout 初始化顺序、CRLF hash 和无界 barrier 构成。CI workflow 随后改为逐文件运行并保留失败尾部 annotation，便于真实定位。

## 3. 具体修复

- artifact apply：`modified` 条目现在同时比较内容 hash 与 executable mode；只有两者都匹配才跳过；mode-only 变化进入 apply，POSIX 下恢复 `100755`。
- artifact rename：case-only rename 不再被错误当成“已应用”。
- Windows 测试：安全目录清理、完整 await close、timer/ref 清理、有限 timeout/barrier、跨平台路径与 CRLF 处理。
- approval：过期审批先在事务内提交 `expired`/`resolvedAt`，事务提交后清 waiter/广播，再抛 `409 APPROVAL_EXPIRED`。
- sandbox：clone 失败恢复原 `status`/`cleanupState`，不硬编码成 `preserved`。
- SSRF：方括号公网 IPv6 literal 去括号后直接识别，绕过 DNS，并继续执行 CIDR/私网校验。
- durable/swarm：lease/fence、receipt、recovery、budget reservation、replan CAS、artifact GC、子 Agent cancel fence、ATTEMPTS_EXHAUSTED 收敛与双 Runtime 幂等恢复均有回归覆盖。
- CI：Ubuntu/Windows 均逐测试文件执行，`--test-concurrency=4`、`--test-timeout=60000`，环境依赖套件明确列为 skip，不吞失败。
