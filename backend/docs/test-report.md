| 阶段 | 实际运行的验证 |
| --- | --- |
| 1 底座 | 创建真实 Cordis Bundle，调用带令牌的 API。验证事务回滚、幂等提交、请求冲突和版本比较。|
| 2 调度 | 一个三节点任务的两个前驱同时执行，峰值并发为 2。第三个节点收到两份产物。验收拒绝后新 Worker 收到反馈，旧产物保留。非法依赖和无能力候选模型均被拒绝。|
| 3 执行 | 真实 Docker 和 Codex CLI。容器检查 UID、网络接口和只读根目录。分别执行拒绝和批准，验证一次性消费、文件内容和 Diff。使用 Git、真实 PTY、stdio MCP 和取消路径。|
| 4 Provider | 启动 `v0.1.4490` Magpie 可执行文件，发现显式注册模型，流经确定性 HTTP 上游，停止网关后切换原生通路。验证密钥库的认证加密。|
| 5 联调 | 前端公开 API 提交带文件验收条件的任务，读取审批记录并批准。DSH 接收流式工具参数并调用 Codex，验收会话读取执行证据。查询产物 `proof.txt` 的实际内容、使用量和记忆，断线游标重放 SSE，并从新服务实例读取相同交付。|
| 恢复 | 在独立 Node 进程调用上游时强制终止服务，启动新进程并读取同一 SQLite 数据目录。租约到期后第二个 Planner 接手，原任务最终只发布一份产物。另测双连接的旧租约写入拒绝、暂停、恢复和取消。|

模型响应由测试进程生成，供应商侧测试密钥只对本地 fixture 有效。生产入口挂载 DSH 与 HTTP Provider Adapter。测试覆盖实际网关、执行器、进程、数据库和网络协议。复现用例见 `test/`，单独运行集成链路使用 `npm run test:integration`。
