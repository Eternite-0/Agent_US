# Agent_US 2.3.6 — 真实模型工具使用验证

## 结论

**2.3.5 确实让同一个真实模型完成了以前做不到的 MCP 发现与故障回退；尚不能证明模型在一般工程任务中更擅长选工具、排顺序或节省成本。**

100 次正式运行中，严格验收由 **39/50（78%）升到 48/50（96%）**。配对结果为升级版独赢 10 对、基线独赢 1 对、均通过 38 对、均未通过 1 对。绝对差为 **+18 个百分点**，但 **5 个净胜来自同一个 MCP 分页任务**。以任务为区组做双侧精确符号翻转，`p = 0.1875`，任务区组 bootstrap 95% 区间约 `[0, +40]` 个百分点；未达到显著性。不能把同一任务的五次重复当成五个独立项目。排除该目录能力不对等任务和一对无法核实基线返回模型的运行后，共同目录任务只提高 **3/44（+6.8 个百分点，p = 0.50）**。

## A/B 设计与控制

- **运行时代码：**前 `ef4454748ca7a2e0a6a587390921e3164c2c911d`（merge 第一父提交），后 `539e86451f7f2e0feef1e358f9bae38d3f1bf26e`（指定 main）。两端都含 2.3.4；两提交之间是 2.3.5 的改动。评测仅增加脚本、测试、报告和证据，不改生产路径、工具定义、Dispatcher 或 Prompt Cache。
- **真实 Provider：**两端各以一个 AccountPool 路由直连受授权的本机 WorkBuddy2API `127.0.0.1:7863/v1`，都请求 `cn:deepseek-v4.1-flash`。所有有响应模型标识的有效流均返回 `deepseek-v4.1-flash`；Provider 的内部路由、模型权重快照与随机种子不可校验。未使用脚本模型、录制回复或匿名网关降级。未记录密钥、认证头或私有推理。
- **调度：**10 个依赖最小的真实代码/工程任务仓库，每任务每端 5 次，配成 50 对。5 条执行通道，每条内部顺序执行、每对相邻执行，按任务序号与重复编号交替 AB/BA（总体各 25 对）；一次计费/失败恢复试跑不计入。每次同路径重建同一 fixture Git commit，独立会话与 SQLite，轮次间不带入会话历史。采集完成时间为 2026-11-23 11:20–11:29（UTC+08:00）。
- **权限与预算：**两端 `approval`，相同工具允许列表、固定单次审批规则、同一 node-permission BenchmarkSandbox，禁止工作区钩子、网络工具与后台命令；只有 MCP 任务配置操作者提供的固定 stdio 服务。仅批准指定文件修改、规定的测试命令及任务对应的 MCP 访问。每轮最多 10 个模型步骤、单次输出上限配置 4,096、总 Token 预算配置 110,000、110 秒等待截止。测试由真实 Node 子进程执行。MCP 数据源是本地可复现服务，不是生产库存 API。
- **独立验收：**隐藏测试在工作区之外、只读执行；复测公开测试、检查未授权文件改动和必要文件产物。严格通过还要求真实运行时 `completed`，并满足任务的必需工具顺序（按场景检查先定位、先复现、最后写入后成功验证，或先获取 MCP 记录）。模型总结不计作通过。独立产物通过与严格通过分别计数。

## 机制、随机性与下一步

1. **已验证的机制收益是可重复的。** 任务 10 基线所有轮次都看不到归档工具，且把主索引的协议级失败当作成功（7 次调用均为 `finished`）；升级版 5 次均记录 `MCP_TOOL_ERROR` 后正确调用归档。任务 09 则相反：基线 5 次读到有效历史日志却都被判 `NON_ZERO_EXIT`，升级版 5 次均正常。MCP 的“有用结果”取已知夹具语义，而不是信任有缺陷的基线回执；若只按运行时 `finished` 数，会误算成 12/17 对 15/20。任务 09 两端最终都 4/5，说明回执修正不保证整轮完成。
2. **同目录能力下的广义改善尚未证实。** 一对基线因连续 `503` 没有可核验的 wire model；主结果保留该对作为真实经历，去掉它则为 +16.3 个百分点，`p = 0.25`。仅看两端全为成功流的 47 对是 39/47 对 46/47；再去掉分页能力差异是 **39/42 对 41/42**。这是事后敏感性分析，不是排除掉失败来提高主通过率。没有触发 Verifier 自动修复事件；因此不能用这批数据量化 2.3.5 的自动验证反馈独立收益。
3. **最高频瓶颈仍是工具选择与约束匹配。** 两端各有 69 次被拒绝的 `bash` 请求，合计占 146 次无效调用的 138 次（94.5%）。常见类别是用 shell 探索仓库或组合命令，却不满足固定审批约束，应使用已有 `glob`、`grep` 或 `inspect_repository`。下一步应独立 A/B 测“模型可见的明确审批边界＋拒绝后推荐已有等价工具”，保持审批本身不变；主要指标预先定为越权命令率、到首次有效动作的步数、复测完成率。再用共同目录能力、更多独立仓库和至少第二个模型检验泛化。
4. **不要把吞吐差异当作效率结论。** 前/后分别发生 12/8 次 HTTP 503、2/0 次传输中止；五路并行共享同一 Provider，不能独立归因给 Agent。38 对双过关样本中，总 Token 中位数 30,394.5→29,089.5、墙钟 15.673→15.062 秒，但合计 Token 1,165,645→1,173,010。下一轮应记录网关上游账号与模型版本（不存凭据），设独立配额，并以成功一次实际耗费比较而不是只看中位数。
