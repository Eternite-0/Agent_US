# 2.3.7 A/B protocol

Frozen runtime revisions: before `3ea6b57c6d2889c775d3ccda28d2f165e7300682`; after `1672ea151703f04aa7c6bfcf7273ea1ad5d5b028`. No historical runs are reused. Same local WorkBuddy2API route, OpenAI-compatible SSE, requested `cn:deepseek-v4.1-flash`. Results measure this model on these tasks, not a population of providers. The gateway does not expose weights, account assignment, or seed.

Use all ten 2.3.6 tasks unchanged and four additional fixtures (deployment overlays, SQL migrations, static-site links, binary packet decoding), with five repeats per arm. Use upstream 2.3.6 runner: five lanes, contiguous pairs within lanes, parity-based AB/BA order, fresh session/fixture/workspace DB each time. Same allowlists, single-call approval, deadlines, budget, sandbox, independent judge, order assertions and unchanged model task prompts. No reruns/replacements for failures. Bash is on the allowlist for the two new code tasks and off for the two new documentation tasks (same rule as original tasks). The model may still request any advertised tool or hallucinate one. Denials count even if a turn later passes.

Primary comparison: number of Bash pre-effect policy/approval refusals per scheduled run (not conditional on Bash use or passing). Use a two-sided exact sign flip on paired count differences, sharing one sign across repeats of each task. Also report refused / all Bash attempts; break out trials where Bash is actually allowed and where it is not. As in 2.3.6, invalid = rejected/no receipt result/unfit; fit = pre-existing task-usefulness rubric, not an optimality oracle. Strict pass requires hidden artifact check, public check if applicable, zero unauthorized changes, required ordering and completion. Report all assigned trials, failures and no-response/usage coverage; healthy-wire-only sensitivity separately, not instead. Secondary outcomes are descriptive. A lower conditional latency is not automatically a speedup if fewer trials perform valid work.

First effective tool latency: wall time from turn start to first observed result of a task-fit, non-meta operation with a successful receipt, excluding unmatched glob/grep; include a required failing reproduction test (exit 1) when it matches the approved command. Exclude `update_plan` and `read_blob` for this timing definition. Timing is observed by the same event subscriber for both arms, not reconstructed from model prose. Report missing observations. Duplicates use 2.3.6 canonical args and successful-write epochs. No-match is informational, not necessarily a bad search. Token counts use actual streaming usage; incomplete/failed requests may be unmetered. Do not use fewer validations, throughput at shared load, or schema byte size as substitutes for measured success or billed usage.

A read of a not-yet-created output is not an effective first action: for this latency metric a successful `read_file` must target a known initial file (writing a new file would itself have been effective first). This does not change the historical fit rubric or acceptance. Never count hypothetical model reasons as emitted explanations.
