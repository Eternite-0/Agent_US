### 3.5 P2：`adaptive-swarm.test.js` 全量高并发偶发超时的真实根因与修复（`2.2.3.4`）

- **根本原因定位：** 问题并非环境超时阈值不足，而是 `backend/test/adaptive-swarm.test.js:242-265` 中 `ScriptedAdapter` 条件分支顺序缺陷：`if (lastUser === '启动主任务并调用群体编排' && opts.tools?.some(...))` 放在了 `if (opts.messages.some((m) => m.role === 'tool'))` **之前**。每次 `swarm_orchestrate` 工具返回结果进入下一轮推理时，`lastUser` 仍为原提示文本，导致适配器连续 3 次重复返回 `tool-call swarm_orchestrate` 并触发 `LOOP_THRASHING_WARNING` 重试退避，在大规模并发 I/O 下恰好逼近/超过 `waitTurnDone` 固定 `4000ms` 轮询上限。
- **确定性修复：** 将 `opts.messages.some((m) => m.role === 'tool')` 分支移至首位并累加校验 `swarmToolCalls === 1`，**原封保留 `waitTurnDone` `4000ms` 断言与全部业务断言**。修复后连续多次全量 `npm test` 均在 `3.1s–3.7s` 内稳定通过。
