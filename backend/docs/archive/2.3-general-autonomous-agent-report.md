## 7. 诚实保留的局限性与后续建议

1. **无 `node_modules` 检出环境下的外置类型工具链门禁：** 当目标陌生仓库本地未安装 `devDependencies` 时，`tsc` / `tsd` / `eslint` 无法在离线检出工作区中实际运行（如 `review-option-summary` 已指出的 `npm run check:type:*` 仍需完整 CI/容器环境安装依赖后验证）。后续若需要对此类工具做强门禁，可在受控沙盒内按需启用受信任依赖预装镜像或工作区缓存映射。
2. **`deepseek-v4.1-flash` 样本量与延迟特征：** 当前 external OSS benchmark 共有 `sampleCount = 4`（按分层模型机制保留为 `provisional_low_sample`，不提前赋予稳定高排名）；受本地单代理深度推理吞吐限制，Run 4 单题平均耗时 ~290s（与并发度 `1` 匹配稳定），高并发场景下更依赖独立的 Provider 并发配额或模型异构分流。
3. **大型仓库（>120 文件）深度扩展：** `analyzeRepository()` 默认 `maxFiles = 120` 以严控首次分析延迟与上下文开销；针对超大规模 monorepo，可按任务焦点的子目录多次按需调用 `inspect_repository` 逐层深入。
