## 3. 彻底修复隐藏验收绕过（三域信任边界设计）

为根治被测代码在加载期或测试中调用 `process.exit(0)` / 提前杀进程 / 跳过断言导致外层仍返回 `passed: true` 的漏洞，建立了严格的**三域隔离**：

1. **Trusted Host Judge（`backend/src/evaluation/hidden-acceptance.js` & `BenchmarkSandbox.runHiddenAcceptance`）：**
   - 静态扫描 `extractExpectedTestsFromScript()`（严格禁止并预拒绝任何静态 `test.skip` / `test.todo` 与 0 用例套件）。
   - 计算当前工作区确定性 `artifactDigest`（无符号链接跟随全树内容/符号链接目标 SHA-256，跳过 `.gitStat` 抖动）。
   - 生成单次随机 `hmacKey`（32 字节 Hex）与 `envelopeNonce`（16 字节 Hex），构造只读阶段文件目录 `supervisor.mjs`、`worker.mjs`、测试文件与 `manifest.json`（包含 `suiteSha256`、`workerSha256`、`expectedTests`、`sessionNonce`、`taskId`、`attemptId`、`artifactDigest`），**HMAC 密钥严禁写入磁盘、CLI 参数或环境变量，仅通过短寿命开启后立即关闭的容器/进程 `stdin`（`-i`）单次投递**。
   - 执行完毕后调用 `extractAndVerifyHiddenEnvelope()`：常时间 `timingSafeEqual` 验签、检测并直接拒绝对标准输出/错误流中伪造或重复注入 `<<<AGENT_US_HIDDEN_ENVELOPE_V1>>>` 块的行为、核对全部上下文绑定字段及每条用例 `started === true && completed === true && passed === true && !skipped && !todo && !prematureExit && workerExitCode === 0 && workerSignal === null && assertionCount >= minAssertions`。
2. **Read-Only Container Supervisor（`backend/src/tools/hidden-acceptance-supervisor.mjs`）：**
   - 永不 `import` 工作区代码；校验 `suite.mjs` 与 `worker.mjs` 的运行前 SHA-256 一致性；对 `expectedTests` 中每一项**逐一派生全新的独立 `worker.mjs` 子进程**（防止前后用例共享状态或互相破坏）并使用闭合 `worker_ready -> init(testToken, expectedCount)` 握手。
   - 隔离收集每个 worker 的 `stdout`/`stderr`，一旦捕获任何伪造信封标记即刻置位 `tamperingDetected: true`；缺少完成信号、worker 提前退出、`SIGTERM`/`SIGKILL`、超时或跳过用例均如实记录为失败原因并生成最终带 HMAC-SHA256 签名的权威信封。
3. **Fresh Per-Test Isolated Worker（`backend/src/tools/hidden-acceptance-worker.mjs`）：**
   - 在加载任何测试脚本与被测模块前：捕获私有 `realSend` 并使用 `Object.defineProperty(..., { writable: false, configurable: false })` 彻底封死用户代码调用 `process.send` 伪造 IPC 帧的通道；注入 `uncaughtException` 与 `unhandledRejection` 捕获；
   - 利用 Node 24 原生 `node:module` `registerHooks` 为隐藏测试文件专门映射只读封闭的 `agent-us-hidden:assert` / `assert-strict` / `test` 虚拟模块（不可被 `/work` 被测模块修改或替换，严格统计每一次 `assert.*` 与 `t.assert.*` 断言调用次数，并把所有 `t.skip()`/`test.skip()`/`todo()` 视为硬违规）；
   - 验证已注册测试总数严格等于 `init.expectedCount`，并在异步队列与子测试完全清算且断言数达标后，才在闭环末尾发送携带私有 `testToken` 的完成信号。
4. **Judge 确定性一票否决（`backend/src/evaluation/judge.js`）：**
   - 新增导出 `enforceDeterministicHardVeto()` 并注入 `createDeterministicJudge()`：无论使用默认校验还是 `fallback`（模拟模型评审建议 `passed: true`），只要 `hiddenAcceptancePassed === false`、`hiddenAcceptanceVerified === false`、`hiddenAcceptanceTamperingDetected === true`、`historyUntouched === false`、`baselineTestsUntampered === false` 或 `sandboxIsolated === false`，裁决结果强制锁定 `passed: false, score: 0, hardVetoed: true`。

## 4. 操作系统级强隔离架构、Fail-Closed 策略分级与网络/资源控制

1. **沙箱安全分级（`SANDBOX_TIERS` 与 `SANDBOX_MODES`）：**
   - `SANDBOX_TIERS.STRONG_OS_ISOLATION`（`docker`）：默认且唯一被生产/评估默认路径接受的强隔离级别。`BenchmarkSandbox` 默认 `mode = SANDBOX_MODES.STRONG`；无论是 `STRONG`、`DOCKER` 还是 `AUTO`，当 Docker daemon 或 `agent-us/benchmark:node24` 镜像不可用时，**一律 Fail-Closed 抛出 `SandboxUnavailableError` (`E_SANDBOX_UNAVAILABLE`)，绝不静默降级回 Node Permission Model 或宿主机执行**。
   - `SANDBOX_TIERS.PROCESS_HARDENING_ONLY`（`node-permission`）：明确降格为辅助进程加固层，在缺失 `allowProcessHardeningOnly: true` 显式授权时调用 `resolveBackend()` 一样直接 Fail-Closed（`E_SANDBOX_UNAVAILABLE`），并在能力矩阵与评估证据中如实标注 `strongOsIsolation: false`。
2. **Docker 强隔离运行参数全清单（`DockerBenchmarkSandbox.buildDockerRunArgs`）：**
   - 容器隔离参数：`--rm --init --pull=never --network=none --ipc=none --read-only --cap-drop=ALL --security-opt=no-new-privileges --user=65534:65534 --pids-limit=<N> --memory=<M>m --memory-swap=<M>m --cpus=<C> --ulimit nofile=1024:1024 --ulimit cpu=<S>:<S> --tmpfs /tmp:rw,nosuid,nodev,noexec,size=64m,mode=1777`。
   - 危险挂载预检（`assertSafeDockerMountSource`）：在调用 `assertNoSymlinkEscape` 递归扫描之前先行校验路径，直接拒绝系统根目录（`/`、`C:\`）、`/var/run`、`docker.sock`、`docker_engine`、`/etc`、`/proc`、`/sys`、`C:\Windows`、`backend/var`、`upstream`、`.ssh`/`.aws`/`.gnupg`。
   - 超时、Abort 与异常退出的残留清理：注册 `docker rm -f <containerName>` 回调并在非零退出时同步触发强制清理；经过精确按 `containerName` 清理核查，并发执行完毕后 **0 个残留容器**。
3. **依赖受控准备与离线执行隔离（`backend/src/evaluation/dependency-policy.js`）：**
   - 保留执行期严格 `--network=none` + `NPM_CONFIG_OFFLINE=true` + `NPM_CONFIG_IGNORE_SCRIPTS=true` + 本地 `127.0.0.1:0` 代理黑洞。
   - 新增 `prepareDependencies()` 受控准备阶段：强制校验证书安全受信任 HTTPS Registry、锁定精确 semver、强制 lockfile 完整性检查（开启 `requireLockfileIntegrity` 时）并生成 `--ignore-scripts --no-audit --no-fund --offline/--registry=...` 安全参数，确保任何测试运行期间网络彻底关闭（实测宿主机 `127.0.0.1` IPv4 金丝雀、`[::1]` IPv6 金丝雀、`host.docker.internal` 网关、DNS lookup 及 Python `urllib` 全部 100% 拦截且金丝雀命中次数 `0`）。

## 5. Docker 文件权限、Linux `65534:65534` 兼容与 Windows NTFS 实测验证

针对此前暴露的“`0o400`/`0o500` 宿主机挂载权限导致容器 `65534:65534` 不可读”缺陷，完成了跨平台双路径治理与真实验证：

1. **POSIX / Linux（Ubuntu CI）精准暂存架构：**
   - `BenchmarkSandbox.runHiddenAcceptance()` 将外部目录（`0o700` 宿主侧私有外壳）下的隐藏套件文件写为 `0o444`、目录写为 `0o555` 并在挂载选项加 `:ro`，`finally` 中先恢复可写再递归 `rmSync`。
   - `DockerBenchmarkSandbox.execArgv()` 在非 Windows 平台下为 `workspaceRoot` 与 `readOnlyDirs` 创建受 `0o700` 外壳保护的临时镜像区：对只读挂载统一赋权目录 `0o555`/文件 `0o444`，对可写工作区赋权目录 `0o777`/文件保留可执行位 `+x`（跳过 `.git` 不可变对象直接覆盖写导致 `EACCES`），运行并完成 `assertNoSymlinkEscape()` 后将增量改动安全同步回源工作区并清场。在 `ubuntu-latest` CI（Run `45119822101`）真实 Docker 下 100% 验证通过。
2. **Windows 11 Docker Desktop NTFS Bind Mount 实测验证：**
   - 实测隐藏目录以 `:ro` 绑定挂载至 `/agent-us-ro/0`：容器 `uid=65534(nobody)` 可正常加载执行 `supervisor.mjs`、`worker.mjs` 与 `hidden-acceptance.test.mjs`，对自身与 `manifest.json` 写入立即触发内核级 **`EROFS` 只读拒绝**；
   - 实测工作区以 `:ro` 挂载时任何写/删操作均返回 **`EROFS` / `EACCES`**；以 `:rw` 挂载时支持创建混合大小写子目录 `subDir/CaseFile.txt`、写入、删除文件与 `rmdir`；根目录 `/` 写入被 `--read-only` 根文件系统阻塞（`EROFS`）；
   - 实测 NTFS Directory Junction 与跨工作区符号链接逃逸在启动容器前即被 `assertNoSymlinkEscape` 精准识别并抛出 **`E_SANDBOX_SYMLINK_ESCAPE`**。
