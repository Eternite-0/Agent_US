## 1. 目标达成与核心结论总览

1. **彻底移除宿主机直跑与环境变量继承：** 审计并消除 `external-benchmark.js`、`dataset.js`、`fixtures.js`、`service.js`、`direct-agent.js`、`child-lifecycle.js` 与 `repo-intelligence.js` 中的 `makeCleanTestEnv()`、`runCommandSync()`、`{ ...process.env }` 与宿主机 `execFile`/`execFileSync`/`spawnSync` 直跑路径，统一接入 Fail-Closed `BenchmarkSandbox` 与 `runHardenedGit`/`runHardenedGitSync`。
2. **严格 Fail-Closed 双层沙箱基础设施（`backend/src/tools/benchmark-sandbox.js`、`benchmark-sandbox-preload.mjs`、`backend/sandbox/Dockerfile.benchmark`）：**
   - **Tier 1 (`DockerBenchmarkSandbox`)**：`--network=none --read-only --cap-drop=ALL --security-opt=no-new-privileges --user=65534:65534 --pids-limit --memory --memory-swap --cpus --tmpfs /tmp:...`，超时即 `docker rm -f`。
   - **Tier 2 (`NodePermissionBenchmarkSandbox`)**：跨 Ubuntu 与 Windows Node 24 原生隔离——使用 `--permission --no-addons --max-old-space-size`、预执行符号链接/NTFS Junction 逃逸扫描、`realpathSync.native` 短路径规范化、`--import` 不可变预加载网络/原生绑定/进程封锁、`--test-isolation=none` 与 Linux `prlimit --cpu` + POSIX `SIGXCPU` 信号映射 + JS CPU 看门狗 + `killProcessTree`。
   - **Fail-Closed 红线**：任一已配置或探测后端不可用时直接抛出 `SandboxUnavailableError`（`code: 'E_SANDBOX_UNAVAILABLE'`），**永不降级**回 `HostSandboxAdapter` 或宿主机直接执行。
3. **严格 Allowlist 环境变量构造（`buildStrictSandboxEnv`）：** 始终从 `{}` 构建，仅允许操作系统运行必需基础键（`PATH` 及 Windows 系统运行时最小集）；强制剥离所有 Provider Key、`GITHUB_TOKEN`、`NPM_TOKEN`、`DATABASE_URL`、`NODE_OPTIONS` 等宿主变量，并将 `HOME`/`USERPROFILE`/`TMP`/`TEMP`/`TMPDIR`/`APPDATA`/`LOCALAPPDATA` 重定向至每次运行的临时隔离目录。
4. **Judge 与被测代码分离：** `BenchmarkSandbox.runHiddenAcceptance()` 在 `workspaceRoot` 之外的只读临时目录创建隐藏验收脚本（POSIX 设 `0o500`/`0o400`），以独立进程运行，并将工作区挂载/授权为只读（`workspaceReadOnly: true`），执行完毕 `finally` 自动清理；历史/基线/依赖策略任一失败时即刻拒绝执行不可信仓库代码（fail-fast）。
5. **显式依赖策略（`backend/src/evaluation/dependency-policy.js`）：** 默认 `offline-only`，强制校验 HTTPS 受信任镜像源白名单（默认仅 `https://registry.npmjs.org/`）、精确 pinned semver（拒绝 `^`、`~`、`*`、`latest`、`git+`、`http:` 等）、禁止生命周期安装脚本（`--ignore-scripts`）并拦截 `npm install`/`npx`/`pip`/`cargo`/`go`/`curl|sh` 安装命令。
6. **合成恶意攻击测试与 4 项 OSS Benchmark 验证全通过：** 新增 `backend/test/evaluation/benchmark-isolation.test.js`（10 个测试组、21/21 通过），覆盖合成密钥泄露、宿主机文件/符号链接与 NTFS Junction 逃逸、`127.0.0.1` 金丝雀网络外发、进程/Shell 注入、受限 CLI 边界、超时/CPU/输出泛洪、Fail-Closed 无回退、`runHiddenAcceptance` 只读防篡改、依赖策略及 `DirectAgentRuntime` 评估会话继承；4 项 OSS Benchmark 与 10 项工程基准均在沙箱内按原严格标准全部通过。

## 4. 沙箱架构与隔离控制细节

### 4.1 双层后端与 Fail-Closed 仲裁（`BenchmarkSandbox`）
- **仲裁逻辑 (`resolveBackend`)**：支持 `mode` 为 `auto`、`docker` 或 `node-permission`（默认读取 `AGENT_US_BENCHMARK_SANDBOX_MODE || 'auto'`）。
  - `docker` 模式要求 `DockerBenchmarkSandbox` 的 `docker info` 与基准镜像检查均可用，否则立即抛出 `SandboxUnavailableError` (`E_SANDBOX_UNAVAILABLE`)。
  - `auto` 模式优先探测 `DockerBenchmarkSandbox`，不可用时探测 `NodePermissionBenchmarkSandbox`（验证当前 `process.execPath` 支持 `--permission` 与 preload 脚本可读可执行）；两者均不可用时直接Fail-Closed 抛出 `SandboxUnavailableError`，**严禁回退 `HostSandboxAdapter`**。
- **Node `--permission` + 预加载加固（`NodePermissionBenchmarkSandbox` & `benchmark-sandbox-preload.mjs`）**：
  - 主进程传递 `--permission --no-addons --max-old-space-size=<mb>`、精确按目录的 `--allow-fs-read=` 与 `--allow-fs-write=`（全部经 `realpathSync.native` 规范化并剔除 Windows `\\?\` 前缀），对 `node --test` 自动注入 `--test-isolation=none`；禁止传递 `--allow-worker`、`--allow-addons`、`--allow-inspector` 与未受限 `--allow-child-process`。
  - 预加载器读取并**立即删除** `AGENT_US_SANDBOX_CONFIG`；在启用任何用户代码前，同时对 CJS `require` 与 ESM `import`（通过 `syncBuiltinESMExports()`）锁定 `node:net`、`node:tls`、`node:http`、`node:https`、`node:http2`、`node:dgram`、`node:dns`、`node:dns/promises` 与全局 `fetch`/`WebSocket`/`EventSource`/`XMLHttpRequest`（一律抛出 `ERR_SANDBOX_NETWORK_BLOCKED`）；不可写不可配置地包装 `process.binding`/`process._linkedBinding` 阻断 `tcp_wrap`/`udp_wrap`/`cares_wrap`/`tls_wrap`/`http_parser`/`pipe_wrap`/`spawn_sync`/`process_wrap`/`worker`/`inspector` 并禁用 `process.dlopen`。
  - **受限工作区 CLI 模式（`allowWorkspaceNodeCli`）**：默认 `false`（不授予 `--allow-child-process` 且锁定 `child_process` 全部导出）；仅对需要 CLI 子进程的自测任务（`oss-nanoid-batch-cli-01`、`real-data-processing-01`）显式开启，且仅允许调用规范化后的当前 `node` 可执行文件、禁止 `shell: true`、禁止 `-e`/`-r`/`--import` 等标志参数、验证目标 `.js`/`.mjs`/`.cjs` 脚本经 `realpathSync.native` 解析仍严格位于 `workspaceRoot` 内（不含 `.git`），限制总派生次数（默认 `maxChildSpawns: 32`），并将完整 `--permission`/`--import` 隔离标志（**移除 `--allow-child-process`** 限制递归深度为 1）与干净 Allowlist Env 强制透传至孙进程。

### 4.2 严格环境变量 Allowlist（`buildStrictSandboxEnv`）
- **构建方式：** 强制 `const env = {}`，仅按 `STRICT_ENV_ALLOWLIST_BASE` 复制 `PATH`（Windows 额外包含最小运行时键 `SYSTEMROOT`、`WINDIR`、`PATHEXT`、`OS`、`PROCESSOR_ARCHITECTURE`、`NUMBER_OF_PROCESSORS`）。
- **注入保护：** 强制将 `HOME`、`USERPROFILE`、`TMP`、`TEMP`、`TMPDIR`、`APPDATA`、`LOCALAPPDATA` 指向每次独立创建并在 `finally` 销毁的临时目录；锁定 `TZ=UTC`、`LANG=C.UTF-8`、`NPM_CONFIG_OFFLINE=true`、`NPM_CONFIG_IGNORE_SCRIPTS=true`、`GIT_TERMINAL_PROMPT=0`、`GIT_CONFIG_NOSYSTEM=1`、`NO_PROXY=*` 与本地死端代理黑洞；并对 `extraEnv` 实施 `FORBIDDEN_EXTRA_ENV_KEYS` 与敏感 Key/Value 正则拦截（`E_SANDBOX_ENV_VIOLATION`）。

### 4.3 文件系统、资源限制与依赖策略
- **符号链接与 NTFS Junction 防护（`assertNoSymlinkEscape`）**：执行前递归扫描 `workspaceRoot`（含 `.git` 目录本身，跳过深层 `.git/objects`），任何指向工作区外或悬空的符号链接/Junction 在启动前即抛出 `SandboxPolicyError`（`E_SANDBOX_SYMLINK_ESCAPE`）。
- **CPU / 内存 / 进程 / 时间 / 输出限制**：
  - Linux 可用 `prlimit` 时直接以 `prlimit --cpu=<N> -- node ...` 实施内核级 CPU 硬截断，通过 `SIGNAL_EXIT_CODES` 正确捕获 `SIGXCPU`（退出码 `152`）并置位 `cpuLimitExceeded: true`；同时在预加载器内附带 `process.cpuUsage()` `.unref()` 看门狗（触发退出码 `137` 与 `ERR_SANDBOX_CPU_LIMIT`）。
  - 内存通过 `--max-old-space-size`（及 Docker `--memory`/`--memory-swap`/`--pids-limit`）约束，Wall-clock 超时触发 `killProcessTree`（退出码 `124`、`timedOut: true`），标准输出与错误流合并上限受 `maxOutputBytes` 保护并标注 `truncated`/`outputTruncated`。
- **依赖策略（`dependency-policy.js`）**：强制校验证书安全的受信任 HTTPS Registry 列表、精确 pinned semver（拒绝 `^`、`~`、`*`、`latest`、`http://`、`git+` 等）、阻止未经允许的生命周期脚本（`preinstall`/`install`/`postinstall`/`prepare`/`prepack`）以及所有包管理器在线安装与 `curl|sh` 命令。
