# Agent_US 2.3.3 显式 Swarm 验收报告

日期 2026 年 11 月 23 日。

## 入口与兼容性

| 输入 | 行为 |
| --- | --- |
| 普通消息 | 进入 `/v1/sessions/:id/turns` 的 `DirectAgentRuntime`，沿用流式回复、工具权限、审批与验收。普通聊天和代码修改均不创建 Swarm Run。 |
| `/swarm <任务>` | 在当前根会话提交持久化 Run。命令回执、对话历史、Run 和首个队列 Job 同事务写入。前端和后端共用解析器，任务正文可以包含中英文和换行。 |
| `/swarm status` | 优先返回本会话的活动 Run，否则返回最近一次 Run。响应包含计划、节点、依赖、成员会话与模型、预算账本及验收结果。 |
| `/swarm stop` | 取消本会话当前 Run，持久化取消节点、Job 及子会话状态，随后中止活动执行。重复提交相同 `clientTurnId` 返回原 Run。 |
| `/swarm` | 返回用法提示。启动命令通过会话工作区取得任务上下文，上传附件由普通聊天处理。 |

活动 Direct Turn 和显式 Swarm Run 在同一会话互斥。命令重试及忙碌保护均在 SQLite 内执行。`/goal`、旧 `/v1/swarm/runs` 入口和 `/api/v1/*` 继续服务原调用方。普通 Direct Turn 保持原有响应格式。命令回执使用既有消息表，历史会话继续使用原协议。

## 执行与交付

- Swarm 通过 Durable Queue 调用现有 Planner、计划校验、Team Optimizer 和 AdaptiveSwarmOrchestrator，子会话使用现有 Tool Runtime。独立任务、依赖、Provider 能力和预算影响每批成员数量。简单目标可派发单个成员，计划持久化其原因。每个 Run 的活动节点上限为 8，Recovery Worker 另有进程级执行槽位。
- 研究和审查节点使用共享只读工作区。写入任务可使用隔离 Worktree。依赖节点通过 CommunicationBus 接收交接，通过 Artifact Manager 读取真实文件和校验摘要。满足条件时独立 Reviewer 检查证据。变更应用到父工作区需要现有的明确确认及权限检查。
- 预算账本记录步骤、Token 的预留和结算。墙钟限制从 Run 提交时开始，覆盖排队、执行和跨进程恢复。Provider 费用估算可参与组队，具体美元花费依赖 Provider 计费，现有账本没有统一的美元硬上限。
- 取消先撤销持久化 Job fence，再向活动进程传播中止。迟到的结果和后续 Job 无法重新取得终止 Run 的执行权。Worktree 清理沿用租约所有权，已发生的外部操作由现有回执和人工核对流程处理。
- 现有聊天入口支持命令提示。Run 面板借用当前 SSE 连接触发刷新，并保留轮询兜底。历史消息可打开对应 Run。面板显示实际计划依赖、各节点工作内容、成员与进度、协作消息、产物、审批入口、预算和最终验收。

## Repository Intelligence

Direct 的 `inspect_repository` 和 Swarm Planner 使用同一个按工作区缓存的渐进索引。每次调用推进有限文件批次，返回完整或部分覆盖状态。文件和目录指纹触发索引刷新，近期同时间戳的修改由内容摘要辅助识别。索引保留仓库忽略规则和受保护路径边界，跳过链接，并限制单文件读取和上下文输出大小。

符号检索返回文件和行号，可从符号双向追踪有限深度的调用链并提取关联测试与有行号的代码片段。静态调用解析以 JS/TS 为主，Python、Go 和 Rust 提供声明索引。动态分派与反射调用仍需查看源码或运行测试。缓存位于进程内，服务重启后按请求重新构建。
