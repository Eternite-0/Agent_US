## 2. Item-by-Item Results for All Six Fix Groups (A–F)

### Fix A — Hook Trust Boundary & Explicit Tool Allowlist (Group 1)
- **A1–A6 (Executable Hook Trust Boundary)**: Added `HookTrustManager` (`backend/src/tools/hook-trust.js`) backed by SQLite `hook_trust_approvals` with canonical realpath + raw-byte SHA-256 content-digest binding and default-deny loading in `HookRunner`. Workspace write tools (`write_file`, `edit_file`, `apply_patch`) invoke `onHookConfigMutated` to revoke prior trust immediately and never auto-approve hooks (including same-turn `PostToolUse`, subsequent steps, and restarts). Modifying a previously trusted file invalidates its digest immediately (`409 HOOK_DIGEST_MISMATCH`).
- **A7–A8 (Hook Execution Hardening & Fail-Closed Preservation)**: Hook process spawning enforces `sanitizeChildEnv`, `AbortSignal` cancellation, and `killProcessTree` timeouts; observation hooks receive zero extra privileges. Preserved security-hook fail-closed blocking, post-transform Zod + policy re-checks, approval `argsDigest` binding, and pre-execution lease guards. Also fixed `ToolDispatcher` `exitCode` regex on `<untrusted ...>exitCode: N` wrapped bash output so non-zero bash exits persist `status='failed', exitCode=N, errorCode='NON_ZERO_EXIT'`.
- **A9–A10 (Explicit Tool Allowlist Semantics)**: Enforced tri-state allowlist semantics (`null`/`undefined` = unrestricted, `[]` = allow NO tools, non-empty array = allow ONLY listed tools) consistently across `ToolPermissionPolicy`, `ToolDispatcher`, `SessionRepo` (`direct_sessions.toolAllowJson/toolDenyJson`), `ChildAgentManager` (`spawn`/`fork`/`resume`), `Swarm` planner/replan/orchestrator (ensuring `read_swarm_artifact` injection never widens explicit `[]`), and crash recovery.

### Fix B — Completion Judgment, Failure Handling & Feedback Isolation (Group 1)
- **B1–B4, B7 (Verification-Derived Terminal Status)**: Added `backend/src/kernel/verdict.js` (`resolveTurnOutcome`, `resolveSwarmOutcome`, `classifyFailureKind`, `safeIsolateSideEffect`). Loop exit is decoupled from verification pass; repair rounds re-verify and fail accurately when reaching the repair cap; final step, step-limit (`STEP_BUDGET_EXHAUSTED`), thrashing (`LOOP_THRASHING_ABORT`), and resumed executions always run final verification before deriving status.
- **B5–B6 (`block_reconciliation` & `reconciling` State)**: `block_reconciliation` parks Direct turns, Child turns, and Swarm runs in recoverable `reconciling` state (`RUN_TRANSITIONS.verifying -> reconciling`), never `completed`.
- **B8 (Plain-Text Chat Path)**: Explicit plain-text no-tool path (`evidenceRequired: false, verificationMode: 'plain_text_no_tools'`) succeeds without forcing tool calls.
- **B9 (Cross-Layer Verdict Consistency)**: Unified Direct, Child, and Swarm terminal semantics (`#handleVerify` respects active node outcomes, budget stops, reconciliation gates, and `EvidenceVerifier` verdicts while preserving true primary node `errorCode`/`errorMessage`).
- **B10–B13 (Error Scoping, Side-Effect Isolation, Truthful Feedback & Idempotent Terminal Events)**: Hoisted `effectiveModel`/`contextWindow` in `direct-agent.js` eliminating `ReferenceError` on pre-model-resolution failures; isolated `modelFeedback.record()`, `store.event()`, and `Stop` hooks via `safeIsolateSideEffect`; migrated `model_feedback.verifiedPass` to nullable `INTEGER` (0-tool samples yield `null` rates instead of fake `1.0`) with explicit `verificationStatus`/`failureKind`/`cancelled`; guarded terminal DB commits & event publishing idempotently (`changes > 0`).

### Fix C — Isolated Worktree Artifact Persistence & Handoff (Group 2)
- **C1–C5 (Archive-Before-Complete & Verifiable Bundles)**: Added `SwarmArtifactManager` (`backend/src/swarm/artifacts.js`) storing complete isolated worktree changes (tracked modifications, untracked additions, deletions, renames, binary content, and `100755` file modes) on disk (`<artifactStoreDir>/<runId>/<artifactId>/{manifest.json,files/,changes.patch}`) and in SQLite `swarm_artifacts` + `swarm_nodes(latestArtifactId, artifactUrisJson)` BEFORE marking turns/nodes completed. Archive failures block completion and preserve dirty worktrees.
- **C6 (Real Predecessor Handoff)**: Successor nodes receive verified predecessor artifacts via `.agent-us-handoff/<nodeKey>/` materialization (isolated worktrees), structured `[Predecessor Artifacts (Verified)]` prompt context, and the read-only `read_swarm_artifact` tool (without widening explicit `allowTools: []`).
- **C7 (Guarded Apply-to-Parent & REST API)**: Separated `archiveWorktree`, `verifyArtifact`, and `applyToParent` (enforcing `read-only` denial, `approval` gate, and `baseSha256` conflict detection returning `status: 'conflict'` while preserving both parent edits and archived artifacts). Mounted REST endpoints `GET /v1/swarm/runs/:id/artifacts`, `GET .../artifacts/:artifactId`, `POST .../verify`, and `POST .../apply`, synced into `backend/client/index.ts` and `frontend/src/api/{runtimeClient,client}.ts`.
- **C8–C10 (Dirty Worktree Preservation, Recovery Rehydration & Fence Binding)**: Only archived/discarded/safe worktrees are cleaned up; interrupts preserve dirty worktrees and rehydrate them via `rehydrateExisting: true` (or enter `reconciling` with `WORKTREE_STATE_LOST` if recorded writes are missing on disk). Stale attempts/fences are rejected with `LEASE_LOST` and blocked from touching newer worktrees or artifacts.

### Fix D — Recovery Ownership, Leases & Late Write-Backs (Group 2)
- **D1–D4 (Multi-Runtime Ownership Classification)**: Added `runtime_workers` liveness table and `classifyJobOwnership` (`backend/src/durable/lease-guard.js`) checking lease expiry, explicit `stopped`/`dead` status, and local OS PID liveness. Joining runtimes never steal active non-expired leases, cancel live/pending jobs, or falsely flag live executing tool receipts.
- **D5–D7 (Transactional Lease Fencing Inside `store.tx()` & Terminal Immutability)**: Enforced `assertJobOwnershipInTx`/`assertLeaseInTx` atomically inside SQLite transactions across `direct_turns`, `direct_sessions`, `direct_messages`, `runtime_checkpoints`, `nexus_usage`, `swarm_runs`, `swarm_nodes`, `swarm_artifacts`, `child_notifications`, `worktree_leases`, and `budget_ledgers`/`budget_reservations`. Stale workers encountering `LEASE_LOST` exit cleanly without corrupting active/completed/cancelled states.
- **D8–D9 (Unknown Side Effects & Idempotent Recovery)**: `inspectInterruptedTurn` handles both `executing` and `outcome_unknown` non-replayable receipts (skipping live owners); repeated `recoverOnStartup` and `recoverInterruptedSwarmRuns` invocations are strictly idempotent.

### Fix E — Atomic Replan Cap & Task-Tree Budget Ledger (Group 3)
- **Part 1 (Atomic Replan Cap & Same-State Metadata Protection)**: Updated `node-state-machine.js` to persist non-terminal same-state metadata patches (`planVersion`, `replanCount`, `budgetJson`, `usageJson`, Group 2 ownership columns) with CAS predicates (`expectedPlanVersion`, `expectedReplanCount`) while strictly rejecting terminal-state metadata overwrites (`INVALID_SWARM_TRANSITION`). `DynamicReplanner` executes all 3 strategies (`retry_same`, `switch_model`, `split_subgraph`) inside one synchronous `store.tx()` with CAS and `UNIQUE(runId, version)` index so concurrent node failures produce monotonic versions and never exceed `maxReplans`. Added `STEP_BUDGET_EXHAUSTED` to `BUDGET_ERROR_CODES` and `NON_REPLANABLE_ERRORS`.
- **Part 2 (Task-Tree Budget Ledger & Cross-Group Multi-Runtime Safety)**: Added `TaskTreeBudgetLedger` (`backend/src/swarm/budget-ledger.js`) backed by `budget_ledgers` and `budget_reservations` with atomic `BEGIN IMMEDIATE` admission, reservation, controllable `maxOutputTokens` clamping, actual usage settlement, unused-balance release, and `estimationErrorTokens`/`overageSteps`/`overageTokens` tracking across `planning`, `node_execution`, `review_verification`, and `replanning` scopes. Explicit `0` means exhausted (never unlimited), `null`/`undefined` means unlimited, and per-node caps are clamped via `min(nodeCap, treeRemaining)` without widening. Cross-group merge hardening ensures `reconcileAfterRestart()` skips reservations owned by live workers (`classifyJobOwnership`), `reserveInference`/`settleReservation` enforce `assertLeaseInTx(leaseGuard)`, and synthetic orphan estimates stay in `budget_ledgers` without polluting authoritative `swarm_runs.usageJson`.

### Fix F — Scheduler Durability, Concurrency, Frontend/SDK Contract & CI (Group 4)
- **Part 1 (Durable Scheduler Convergence)**: Atomically linked `scheduled_task_runs`, `runtime_jobs`, `direct_sessions`, and `direct_turns` inside synchronous `store.tx()`; repaired `queued` runs with `jobId=NULL` on retry & startup `reconcileRuns()`; re-attached deterministic `clientTurnId = run.idempotencyKey` without duplicate turns; converged `scheduled_task_runs` and `scheduled_tasks` monotonically by `runSeq` (`lastStatusRunSeq`/`lastStatusRunId`) inside all committed terminal/cancel `direct-agent.js` DB transactions (`completed`, `failed`, verification-failed, `cancelled`).
