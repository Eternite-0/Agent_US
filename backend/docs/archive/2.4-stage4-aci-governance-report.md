### 3.1 Run 4A-2 (`b694916f`) 暴露的五大校准根因

在 `b694916f` 上执行的首轮 16 试次校准冒烟（`bench-s4-smoke.jsonl`）中，尽管 Arm B 与 Arm C 均实现 `3/4`（75%）超过 Arm A `2/4`（50%），但完整轨审计暴露了 5 项严重失真，致使 Arm D 跌至 `2/4`、`cacheHitRate` 跌至 `0.5414` 且 `aci-04` 四臂全灭（`0/4`）：

1. **`[ACI-REF]` 恢复指令诱饵导致 9/9 次 `expand_context` 全部恢复诱饵文件：** 原先对 `IRRELEVANT` 与 `DUPLICATE` 仍输出 `[ACI-REF artifact://... | restore: expand_context(...)]`，诱导大模型主循环浪费步数去展开明显无关的遗留文件。在 `bench-s4-smoke.jsonl` 中，**全部 `9/9` 次恢复均指向诱饵**（`B`: `COMPLIANCE-APPENDIX.md`, `v0-path-normalizer.js`；`C`: `legacy-v0-evaluator.js`, `v0-path-normalizer.js`, `v0-policy-rules.js`, `CHANGELOG.md`；`D`: 同前三文件），`DEFER` 产出为 `0`。
   - **修复 (`2bce1db6`)：** `formatAciRefStub` 将 `IRRELEVANT`/`DUPLICATE` 改为无 `expand_context` 诱饵的 **`[ACI-SKIP ...]`** 存根，`DEFER`/`SUPPORTING` 继续保留 `[ACI-REF ...]`，并在 `aci-engine.js` 的 `isAciStubText` 中双匹配两类前缀。
2. **`6000` 字符直通上限过高 + JSON 缺大纲 + 混合 `grep:` 误杀：** `aci-03` 的 `CONTRACT.json`（`5,787` 字符）与 `aci-04` 的 `policy-engine.js`、`templates/audit-report.html`（`3,576` 字符）均落入 `<= 6000` 直通白名单而完全绕过选择性准入（`0` 次结构压缩），且 JSON 无大纲；同时 `aci-03 D` 第 6 步包含正常文件的混合 `grep:` 结果因前 16 行中偶现一条 `legacy` 路径而被 `isDecoyCue` 误判为诱饵。

## 6. 诚实局限性与实测异常记录（禁止掩饰或夸大结论）

1. **为什么 Phase 4B 中 Arm C（`9/12 = 75.0%`）整体通关率高于 Arm D（`6/12 = 50.0%`）？**
   - **`aci-04` 揭示“完成度 vs 基座模型能力边界”差异：** 在 `aci-04` 中，Arm D 实现了 **3/3 完整执行至 `completed`**（`190,143` / `195,387` / `199,315` tok < `220k` 限额，`0` 次 `TOKEN_BUDGET`），且每次皆通过 `2/3` 隐藏安全测试：仅 `rep=0` 在 `test-2` 报 `AUDIT_REPORT.json` 摘要不一致（`'afa8fc7b...' !== '3b966da7...'`），`rep=1` 与 `rep=2` 在 `test-1` 报 `evaluateAccessPolicy` 直接透传路径异常而非返回拒绝策略。全部 3 次均属 **`model_capability` (`hidden_acceptance_failed`)**，而非上下文机制截断（相比之下 Arm A/B 在 `aci-04` 主要撞 `TOKEN_BUDGET`/`TURN_DEADLINE_EXCEEDED`）。
   - **DTOC 触发与尾轮预算边际：** Arm D 在 `aci-01..03` 共触发 4 次单步 DTOC epoch（`aci-01 r0/r2`, `aci-02 r0`, `aci-03 r2`，共节省 `6,131` tok）；其中 `aci-01 r2`、`aci-02 r0`、`aci-03 r2` 三例虽均已使隐藏验收 **`3/3` 全过**，仍因多轮修改后逼近 `160k` 而在最终收尾前触及 `TOKEN_BUDGET`（Arm C 因 `dtocEnabled=false` 保持 `0` 次历史压缩、仅靠注入前准入从而避开此边界）。
2. **端到端总 `tokenReduction` 为负值的真实统计原因：**
   - Arm B/C/D 的端到端总 token 相对 Arm A 为 `-5.83%`、`-13.81%`、`-8.18%`，并非准入压缩失效（注入前 `admissionTokenReduction` 分别实省 **`54.78%` / `64.83%` / `64.23%`**，累计减负 `53.0k` / `82.3k` / `77.4k` tokens），而是因为 **Arm A 中 `8/12` 试次过早失败截断**（`7` 次 `TOKEN_BUDGET` + `1` 次 `40,539` tok 即挂的超时），大幅压低了 Arm A 分母均值；Arm C/D 得以走完更长程推理链与多轮测试修复。此外，在 `aci-01..03` 全部 `12` 个失败试次中，有 **`11/12` 在截止前已让隐藏测试达到 `3/3` 全过**，仅缺最终证据清单收口步，表明 `160k` 预算对带修复回合的任务偏紧。
3. **上游网关 SSE 缓存缺失（`8/48`）与 `~20k` `prompt_tokens` 异常峰值：**
   - `48` 次试次中共有 **`8` 次收到 `cacheReadTokens = 0`**（`Arm A`: `3` 次 — `aci-03 r1`, `aci-04 r0/r1`；`Arm B`: `5` 次 — `aci-01 r1`, `aci-02 r0`, `aci-03 r0/r1`, `aci-04 r0`；另有 `aci-02 C r0` 仅得 `128 / 129,848 = 0.10%`），导致 Arm B 整体缓存命中率被拉低至 `51.57%`（SSE 完整上报子集为 `71.20%`）。Arm C/D 全 `12/12` 上报均稳定维持 `79.00%` 与 `84.78%`。
   - **Arm C 3 次 `~20k` `prompt_tokens` 峰值：** `aci-01 C r0 s5`（`20,235`）、`aci-04 C r0 s5`（`20,636`）与 `aci-04 C r2 s3`（`19,775`）单次汇总占 Arm C 全部 Supervisor 输入的 `60,646 / 107,398` tokens。因单请求 `mergeUsageSnapshot` 已杜绝多片乘法 bug，且本地 `userPayload` 仅 ~`1–3k` 字符，该 `~20k` `prompt_tokens` 实测来自上游网关在特定请求窗口下的服务端计费上报（可能与网关侧长系统缓存计数回传有关）。
4. **超时回退、网关长尾与 Arm C 偶发诱饵回读：**
   - **Supervisor 回退 `12/68`（`17.6%`）：** Arm C `4/33`、Arm D `8/35`（多为 `25,000ms` 超时，外加 Arm D 两次 DTOC 结构化输出耗时 `5.3s`/`7.9s` 异常），所有回退均安全降级至确定性规则，未导致崩溃。
   - **Arm A 网关长尾超时：** `aci-04 A rep=1` 在 `303,696 ms` 时于仅 `40,539` tokens 触发 `TURN_DEADLINE_EXCEEDED`（运行期伴随 `durable.lease_lost` 告警，隐藏测试 `0/3`）。
   - **Arm C 偶发主动回读 `[ACI-SKIP]`（`5/12` 次）：** 即使存根改为无诱饵的 `[ACI-SKIP ...]`，Arm C 下的 `deepseek-v4.1-flash` 仍在 `5` 次调用中主动传参重读被跳过诱饵（`legacy-journal-adapter.js`, `sample-configs.json`, `COMPLIANCE-APPENDIX.md`, `CHANGELOG.md`），而 Arm D 严格保持 `0/6`。
   - **中段重试遥测隔离边界：** 如 Phase 4A-v2 `aci-03 D` 所见，`direct-agent.js` 中段自动重试创建的新 `AgentLoop` 会开启新 `ContextEvidenceLedger`，后续需把重试前 `admissions`/`supervisorCost` 上文延续合并至终端事件账本。
