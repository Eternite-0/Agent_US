# Agent_US 2.3.7 — Capability-Aware Tool Selection 实测报告

**结论：在这台真实 Provider 和这 14 个工程任务上，Agent 更常选择符合任务和权限的工具，使用更少的无效调用完成了同样数量的任务。** 2.3.7 的 Bash 拒绝总数从 **96 降至 27（−71.9%）**，预设主要指标按任务区组做双侧精确符号翻转 `p = 0.000122`。严格通过率是 **68/70 → 68/70**，不能宣称最终成功率提升，也不能把持平当作总体非劣性的证明。

减少的 69 次中，39 次来自不再推荐已经禁用的工具；另外 30 次来自**仍然能用 Bash 的任务**，该子集每个任务的拒绝数也都下降（7 个任务区组，双侧 `p = 0.015625`）。在这个子集，未被拒的 Bash 调用并没有减少（48 → 49）。这说明收益不全来自目录过滤；本实验并没有把工具说明、失败提示与其他目录变化分别消融，不能细分它们各自贡献。出现同一步内多次原生只读查询的轮数为 67 → 68（并非测得的并行加速）；`inspect_repository` 调用 24 → 41。

## 审计与实现

从 2.3.6 已发布的逐调用证据重计，升级侧的 69 次 Bash 拒绝并非同一问题。**29 次 `POLICY_DENIED`** 出现在本来不允许 Bash 的任务：Direct 把工作区工具交给 AgentLoop，只从目录中去掉沙箱强制禁用项；会话 allow/deny 列表在 Dispatcher 中有效，却没有等价地反映在 Provider 的 Schema 中。**40 次 `APPROVAL_DENIED`** 则发生在 Bash 合法可见的任务（首词 `ls` 21 次、`find` 8 次、`node` 10 次、`git` 1 次）。其中既有本应由原生工具完成的路径侦察，也有给测试命令加管道、重定向或包装退出码的请求。两种都不是靠给 Bash 多授权能正确解决的。

- **调用前：**Direct 每个模型步骤从已注册工具和实时策略生成仅含 `name/description/parameters` 的目录。命令型工具只按与 Dispatcher 共用的名字规则剔除；是否能执行仍取决于真实 `command`。非命令工具使用策略本身对元数据的判定，`deny` 不广告、`ask` 标审批。空 allowlist 保持为空，不猜测任务意图去封锁可能有用的工具。MCP 不因名称或远端自述为只读即降低风险，仍使用本地注册的外向工具元数据。
- **选择与组合：**在 Bash 自身说明中按当前目录列出实际可用的路径、文本、仓库入口和文件读取替代工具；测试命令应独立执行、保留真实退出状态。已有的同批独立只读调度、并发上限及写入屏障不变。没有增加选择模型、预处理 LLM 调用或长系统提示，也没把审批白名单暴露为可复用授权。
- **失败后：**只有带有执行前拒绝回执的 Bash 调用才收到这类选择反馈。无路径、无复合语法的简单目录侦察可以提示另行获准的只读查询；其他拒绝只告知未执行、不得绕过和如何报告阻塞。不替模型执行替代调用，不把权限拒绝改成成功。`glob`/`grep` 真正零匹配时提示改变过滤条件，不宣称文件不存在，也不屏蔽后续查询。
- **不变项：**原始工具实现继续交给 Dispatcher；执行时政策、人工批准、变参校验、permit、回执、沙箱和 MCP 协议均未放宽。没有改 Prompt Cache、ContextAssembler、Swarm 或调度架构。Direct 会话中途从 `approval` 收紧到 `read-only` 的回归测试验证：刚广告过的写入仍被拒并留存 `POLICY_DENIED`，磁盘没有副作用，下一次请求也不再广告它。

## 对照设计与可复现性

- 相邻运行时版本：`3ea6b57c6d2889c775d3ccda28d2f165e7300682` → `1672ea151703f04aa7c6bfcf7273ea1ad5d5b028`。正式两组同期重新运行，未拿 2.3.6 历史通过率充当对照。基线和候选各有独立 worktree，评测器开跑时检查 revision 和运行时源码状态。
- 本机授权 WorkBuddy2API `127.0.0.1:7863/v1`，请求 `cn:deepseek-v4.1-flash`。14 个任务，每版每任务 5 次；70 对、140 轮、AB/BA 各 35 对。相邻配对，五条通道共享同一路由。原 10 项保留同一任务文本、仓库 commit、修正过的隐藏测试和严格判分逻辑；新增 staging 配置、SQL 迁移链、静态站点链接和传感器包解码四个离线工程夹具。它们是可复现的小仓库，不是生产系统或大型第三方项目。
- 每轮新会话和 SQLite、同一 fixture commit、单次审批、同一 node-permission 沙箱和禁用工作区 hooks 的规则。10 步、单次最大输出 4,096、总 Token 预算 110,000、110 秒截止。严格通过要求独立产物、无越界改动、公开复测、必要顺序及运行时完成；隐藏判题在模型工作区之外执行，两组相同且不看模型自评。
- [指标协议](../evidence/archive/2.3.7/protocol.md)、[逐轮及逐工具轨迹](../evidence/archive/2.3.7/traces.jsonl.gz)、[文件产物](../evidence/archive/2.3.7/artifacts.tar.gz)、[机械汇总](../evidence/archive/2.3.7/summary.json)。轨迹含参数、结果状态、可获得的同一步公开用途说明、回执耗时、结果送达时间、变动文件、Provider 每步目录和用量。未发出的调用理由保留为 `not_emitted`；不会记录私有推理或伪造理由。首个有效结果耗时、选择适配和无效调用是三种不同指标，不能相互替换。

复现：用已安装依赖的两个指定 revision 的 worktree 作为 `BEFORE` 和 `AFTER`，`OUT` 使用新的空目录。`TI_BENCH_KEY` 通过安全方式注入环境，不能放入仓库或输出日志。

```sh
export TI_BENCH_SUITE=2.3.7
mkdir -p "$OUT"
for lane in 0 1 2 3 4; do
  node backend/scripts/benchmark-real-model-tools.mjs "$BEFORE" "$AFTER" "$OUT/lane-$lane.jsonl" "$lane" 5 5 &
done
wait
node backend/scripts/summarize-capability-selection.mjs "$OUT"/lane-*.jsonl
# 不调用模型的证据复核；在新建目录解包本报告随附的归档。
E=backend/docs/evidence/2.3.7
V=$(mktemp -d)
tar -xzf "$E/artifacts.tar.gz" -C "$V"
node backend/scripts/verify-capability-artifacts.mjs "$E/traces.jsonl.gz" "$V/artifacts"
```
