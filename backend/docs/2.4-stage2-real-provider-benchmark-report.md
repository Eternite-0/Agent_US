## 5. 客观边界分析与 Stage 3 演进路线图

### 5.1 为什么 Candidate 在效率、缓存与预算生存率大幅领先下，`finalTaskSuccessRate` 仍停留在 `0.2–0.3`？

1. **单次重复随机方差 + 基线提前退场造成的“幸存者偏差”：**
   - 每轮 `--repeats 1` 下单项任务仅有 1 次 LLM 采样（如 `ar-03`/`ar-05`/`ar-08`/`ar-09` 在 Run 2、Phase 2A、Run 3 间存在单次波动）。
   - 更具实质意义的是归因结构迁移：Run 3 中 Baseline 有 **`5/10` 题**直接因 `TOKEN_BUDGET` 崩溃提前淘汰（`ar-04,05,07,09,10`），仅剩 1 次 `model_capability`；而 Candidate 成功护送 **`ar-04, ar-07, ar-09, ar-10`** 全部活到正常交卷阶段（`TOKEN_BUDGET` 仅剩 `2/10`），结果将 `deepseek-v4.1-flash` 自身在边界断言/隐含输出契约上的 `5/10` 模型能力盲区（`ar-01` `CONTRACT.json`、`ar-04` `name: ''`、`ar-07` `undefined` vs `'8080'`、`ar-09` 哈希摘要、`ar-10` 漏掉 `'beta'`）完整暴露于隐藏验收裁决之中。
2. **为什么 Run 3 中 `budgetPruneCount` 仍为 `0`（`ar-03` 余 `13,988` / `ar-05` 余 `3,492`）：**
   - `tryEmergencyBudgetPrune` 设计为仅在 `reserveInference` 抛出 `TOKEN_BUDGET` 的最后一刻才触发被动急救。
   - 在 `ar-03` 中，步骤 19 测试刚跑完时累计用量已达 `146,012`（余量 `13,988`），`MultiStageCompactor` 已在常规上下文阶段完成了重复读去重；进入下步若剩余窗口不足以在扣除工具 schema + 最近上下文窗口后降到严格小于 `remaining`，或模型直接按最后一步重放超出，导致急救未能救回这一步；而在 `ar-05` 中，step 17 `write_file` 后进入再次验证修补轮时余量已低至 `3,492`，低于工具 schema 与最小保留上下文之和（`availableTokens <= ~toolSchema + recent`），任何零 LLM 裁剪均无法在 `3,492` token 内发出新请求。
3. **`ar-08` 自写测试循环触发误熔断与 `ar-09` 哈希摘要策略摩擦：**
   - `ar-08` Run 3 源码修复实际上已通过 Docker 隐藏测试（`hid=true`），但模型在临近收尾（截至第 20 步）反复微调自己编写的 `test/recovery.test.js` 验证期望，被 `ExecutionReasoningTracker` 当成普通源码修复死循环 (`edit_test_fail_loop`) 于 step 20 熔断。
   - `ar-09` 中模型两度触及策略拦截 (`pol=2`) 后未能借助辅助命令校验产物哈希，最终交卷产物与 reviewer 摘要十六进制串不匹配（`'ed47ea...'` vs `'3797f8...'`）。

### 5.2 Stage 3 针对性工程路线图

1. **前移式轻量文件上下文瘦身（Preventive Pre-Turn Trimming）：** 不等待 `TOKEN_BUDGET` 末步急救，而是在步骤 `>= 8` 且累计消耗超过 `60%` 预算或单步输入 > `10k` tokens 时，自动将早期已消费完毕的 `> 4 KB` 非报错文件内容折缩为结构化引用（保留文件路径、行号范围、关键符号与 SHA 指纹），将单步重放上下文长期压低在 `6k–8k` tokens 内，避免 `ar-03`/`ar-05` 在第 17–19 步才被累计 token 挤爆。
2. **区分“自写测试断言调优”与“源码修复死循环”：** 在 `ExecutionReasoningTracker` 中识别连续编辑目标若全部落在非基线、本轮新建/自建的 `test/*` 文件（且基线回归测试未退化）时，给予温和的断言校准提醒或放宽熔断阈值，避免把 `ar-08` 类“源码已绿、仅在调整新建单测”推进成 `LOOP_THRASHING_ABORT`。
3. **只读文件摘要/哈希安全能力补齐：** 在不放松沙箱安全策略前提下，为 Agent 提供只读、确定性、限界的辅助检查原语或内置文件 SHA-256 摘要查询能力，消除模型为计算产物哈希而反复试探被拒的 `node -e` 命令并从源头消灭手算虚假哈希 (`ar-09`)。
4. **多重复统计学严谨评估（`--repeats >= 3`）：** 在上述机制落地后执行多重复配对基准测试，并联合更高推理能力梯度的旗舰模型做横纵双向对比，将单次采样方差与系统机制增益彻底剥离。
